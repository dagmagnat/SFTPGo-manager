# SFTPGo-manager

Личный файловый сервер на **SFTPGo** для Ubuntu 24.04. Доступ через браузер
компьютера и телефона, отдельная панель администратора, пользователи с разными
правами и автоматический HTTPS через Caddy.

Проект подготовлен для репозитория **dagmagnat/SFTPGo-manager**.
[Как загрузить файлы в GitHub](docs/PUBLISH.ru.md).

## Настройки

| Параметр | Значение |
|---|---|
| Домен | `e-cloudfiles.ru` |
| IPv4 VPS | Запрашивается при установке |
| ОС | Ubuntu 24.04 |
| SFTPGo | `drakkan/sftpgo:v2.7.5` |
| Caddy | `caddy:2.11.4-alpine` |
| Каталог установки | `/opt/e-cloudfiles` |

Установщик спросит публичный IPv4 вашего VPS. IP не хранится в исходном коде.
Для другого домена измените `DOMAIN` в начале установщика.
Скрипт рассчитан на новую установку; повторный запуск поверх существующих данных
останавливается. Это установщик, а не механизм обновления.

## Установка

1. В DNS создайте **одну A-запись** `@ → YOUR_SERVER_IP`. Уберите прежние
   A-записи именно корневого домена, если они больше не нужны. На время этой
   IPv4-установки у него не должно быть AAAA-записи. Остальные записи не меняйте.
2. Разрешите входящие TCP **80 и 443** в firewall VPS и у провайдера, сохранив
   доступ SSH. На сервере должны быть свободны TCP 80, 443 и 18080.
3. Подключитесь к VPS, заменив `YOUR_SERVER_IP` на его настоящий IP:

   ```bash
   ssh root@YOUR_SERVER_IP
   ```

4. После публикации файлов этого проекта в ветке `main` выполните на VPS:

   ```bash
   apt-get update && apt-get install -y curl ca-certificates
   curl -fL --output install-e-cloudfiles.sh \
     https://raw.githubusercontent.com/dagmagnat/SFTPGo-manager/main/install-e-cloudfiles.sh &&
   bash install-e-cloudfiles.sh
   ```

   Команды выше выполняются под `root`. Для другого пользователя используйте
   `sudo` перед `apt-get` и `bash`. Можно также скопировать установщик на VPS
   вручную: [подробная инструкция](docs/INSTALL.ru.md).

При запросе `Enter the public IPv4 address of this VPS` введите IP своего сервера.

Установщик проверит DNS, установит Docker при необходимости, запустит SFTPGo,
создаст учётные записи и настроит HTTPS. Пароли генерируются на VPS и не входят
в репозиторий. Firewall автоматически не изменяется.

## Вход и работа

| Логин | Адрес | Права |
|---|---|---|
| `admin` | [Панель администратора](https://e-cloudfiles.ru/web/admin/) | Создание пользователей и управление правами |
| `owner` | [Файловый менеджер](https://e-cloudfiles.ru/web/client/) | Загрузка, скачивание, переименование и удаление файлов |
| `reader` | [Файловый менеджер](https://e-cloudfiles.ru/web/client/) | Список файлов и скачивание, без изменений и публичных ссылок |

`owner` и `reader` видят одну общую папку. Для работы с файлами используйте
`owner`, для управления пользователями — `admin`. Предпросмотр зависит от
формата файла и браузера.

Начальные пароли выводятся в конце установки. Посмотреть их повторно:

```bash
sudo cat /opt/e-cloudfiles/credentials.txt
```

После изменения паролей в интерфейсе этот файл не обновляется.

Загрузите небольшой файл под `owner`, затем скачайте его под `reader`.
Под `reader` загрузка и удаление должны быть недоступны или отклоняться.

## Данные и обслуживание

Файлы находятся в `/opt/e-cloudfiles/storage/data/shared`, база пользователей —
в `/opt/e-cloudfiles/state`. Данные сохраняются при перезапуске контейнеров.

```bash
cd /opt/e-cloudfiles
sudo docker compose ps
sudo docker compose logs --tail=80 sftpgo caddy
```

[Полная инструкция](docs/INSTALL.ru.md) содержит настройку новых пользователей,
резервное копирование и устранение ошибок. Не загружайте в GitHub содержимое
`/opt/e-cloudfiles`: там находятся файлы пользователей, база, пароли и сертификаты.

## Проверки

GitHub Actions проверяет синтаксис Bash, ShellCheck, конфигурацию Docker Compose
и Caddy. Проверки используют временный пароль и не выпускают сертификат.
Установка Docker через apt, выпуск настоящего сертификата и работа пользовательских
аккаунтов проверяются отдельно на VPS. Развёртывание на ваш VPS автоматически
из GitHub не выполняется.

Перед первым запуском на VPS в Actions дождитесь успешного выполнения workflow
`Check installer`. На момент подготовки архива выполнены локальные проверки
синтаксиса Bash и ShellCheck; серверная установка не выполнялась.
