# SFTPGo для e-cloudfiles.ru

ОС: **Ubuntu 24.04**. Во всех примерах замените `YOUR_SERVER_IP` на публичный
IPv4 своего VPS. Установщик запросит его при запуске; в проекте IP не хранится.

В корне репозитория находится установщик `install-e-cloudfiles.sh`.
Он рассчитан на новый VPS со свободными TCP-портами 80, 443 и 18080.
Если на этих портах уже работает сайт, nginx, панель или другой сервис,
установщик остановится. Не останавливайте рабочий сервис наугад: потребуется
настроить совместное использование существующего reverse proxy.

## 1. Направить домен на VPS

В панели DNS домена замените A-записи корневого домена:

| Тип | Имя | Значение |
|---|---|---|
| A | @ | YOUR_SERVER_IP |

У корневого домена должна остаться одна A-запись с этим адресом.
MX, TXT и записи других поддоменов менять не нужно.
Для первоначальной установки не должно быть AAAA-записи корневого домена:
этот установщик настраивается под указанный IPv4. Если используется Cloudflare,
выберите DNS only. Отдельный CDN для этой установки не нужен.

После изменения дождитесь обновления DNS: в ответе должен остаться адрес VPS.

Проверка из PowerShell:

```powershell
Resolve-DnsName e-cloudfiles.ru -Type A
```

В панели VPS разрешите входящие TCP 80 и 443. Сохраните доступ SSH на своём
SSH-порту. Установщик не меняет правила существующего firewall.

## 2. Скопировать установщик

Сохраните `install-e-cloudfiles.sh` в `D:\Downloads`. Выполните в PowerShell:

```powershell
scp "D:\Downloads\install-e-cloudfiles.sh" root@YOUR_SERVER_IP:/root/
ssh root@YOUR_SERVER_IP
```

Введите пароль VPS, если SSH его запросит. Затем уже в консоли VPS:

```bash
bash /root/install-e-cloudfiles.sh
```

В ответ на `Enter the public IPv4 address of this VPS` введите публичный IP
сервера. Это тот же адрес, который вы указали в A-записи домена.

Если у вас другой SSH-пользователь, загрузите файл в его домашнюю папку и
запустите через `sudo bash install-e-cloudfiles.sh`.

## 3. Что создаст установщик

- Docker Engine и Compose из официального репозитория Docker, если Docker отсутствует.
- SFTPGo 2.7.5 и Caddy 2.11.4 в контейнерах с автозапуском.
- HTTPS-сертификат для `e-cloudfiles.ru` с автоматическим продлением.
- Общую папку с каталогами Documents, PDF, Presentations, Other.
- Три учётные записи с разными случайными паролями:

| Логин | Адрес входа | Возможности |
|---|---|---|
| admin | https://e-cloudfiles.ru/web/admin/ | Управление пользователями, правами и настройками |
| owner | https://e-cloudfiles.ru/web/client/ | Загрузка, скачивание, изменение и удаление общих файлов |
| reader | https://e-cloudfiles.ru/web/client/ | Просмотр списка файлов и скачивание; без изменения, удаления и создания публичных ссылок |

Администратор и пользователь файлового менеджера — разные учётные записи.
Для работы с файлами используйте owner, для настройки прав — admin.
Доступность предпросмотра зависит от формата файла и браузера.

Пароли появятся в терминале после установки. Посмотреть их ещё раз:

```bash
sudo cat /opt/e-cloudfiles/credentials.txt
```

После смены пароля в веб-интерфейсе файл credentials.txt не обновляется:
в нём сохраняются начальные значения. Сохраните актуальные пароли у себя.

Серверная установка проверяет создание reader с правами только list/download
и запретом публичных ссылок. Затем проверяет HTTPS. Дополнительно проверьте
браузером: загрузите небольшой файл под owner и скачайте его под reader.
Попытка загрузки или удаления под reader должна быть недоступна/отклонена.

## 4. Как пользоваться

На рабочем компьютере откройте `https://e-cloudfiles.ru`, войдите под owner,
нажмите Upload Files и загрузите документы в нужную папку.

В другом корпусе или на телефоне откройте тот же сайт, войдите под reader
и скачайте нужные документы. Оба пользователя видят одну общую папку.

Для нового пользователя откройте WebAdmin под admin, раздел Users.
Выберите Local filesystem и домашнюю папку `/srv/sftpgo/data/shared`, если ему
нужны те же общие файлы. Для чтения задайте права `/`: `list`, `download`,
а в настройках WebClient запретите Shares. Для отдельного набора файлов
укажите другую домашнюю папку или настройте Virtual Folders.

## 5. Где хранятся данные

- Файлы: `/opt/e-cloudfiles/storage/data/shared`.
- База пользователей, настройки и служебные данные: `/opt/e-cloudfiles/state`.
- Конфигурация запуска: `/opt/e-cloudfiles/compose.yaml` и `.env`.
- Сертификаты: `/opt/e-cloudfiles/caddy-data`.

Перезапуск контейнера не удаляет эти данные. Резервная копия на другой машине
нужна отдельно. Простой способ получить согласованную копию (с временной
остановкой сервиса):

```bash
sudo bash <<'BACKUP'
set -Eeuo pipefail
umask 077
cd /opt/e-cloudfiles
trap 'docker compose start' EXIT
docker compose stop
tar -czf /root/e-cloudfiles-backup-$(date +%F-%H%M%S).tar.gz -C /opt e-cloudfiles
BACKUP
```

Скачайте архив резервной копии с VPS. Он содержит также базу и начальные пароли.

## 6. Если установка остановилась

Ошибка DNS: исправьте A/AAAA и повторите запуск. На этом этапе папка приложения
ещё не создаётся.

Ошибка занятых портов: сохраните вывод ошибки и выясните, какой сервис уже работает.

Если `/opt/e-cloudfiles` уже создан, установщик не запускает повторную установку
поверх данных. Не удаляйте папку ради повторного запуска. Логи:

```bash
cd /opt/e-cloudfiles
sudo docker compose ps
sudo docker compose logs --tail=80 sftpgo caddy
```

Если не выпустился HTTPS-сертификат, проверьте DNS и доступность портов 80/443
из интернета. Caddy повторяет попытки автоматически. После исправления можно:

```bash
cd /opt/e-cloudfiles
sudo docker compose restart caddy
```

Если остановка произошла при создании owner/reader, admin уже может существовать.
Его пароль сохранён в credentials.txt. Пользователей можно создать через WebAdmin
после восстановления HTTPS; ориентируйтесь на настройки выше.

## Проверка и источники

При подготовке проверены синтаксис Bash, ShellCheck и JSON создаваемых пользователей.
Установщик не запускался на вашем VPS; Docker/HTTPS проверяются при его запуске.
